# AGENTS.md — `hivemind-ovos-agent-plugin`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

This plugin bridges a `hivemind-core` hub to a local OpenVoiceOS message bus.
It forwards HiveMind client payloads onto the OVOS bus, and it routes OVOS
responses back to the client that sent the original message, enforcing client
isolation so one client never sees another's traffic. It also ships a policy
plugin (`OVOSAgentPolicy`) that injects per-client skill/intent blacklists into
the OVOS session before a message reaches skills. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the wire
protocol and specs live in the architecture docs. Related: the
[hivemind-plugin-manager](https://github.com/JarbasHiveMind/hivemind-plugin-manager)
interfaces this plugin implements (`AgentProtocol`, `PolicyPlugin`), and
[hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-bus-client)
for the `HiveMessage`/`HiveMessageType` wire types.

## Layout / build / test

- Package module: `hivemind_ovos_agent_plugin/` (`__init__.py` — the
  `OVOSAgentProtocol` agent, `policy.py` — mutations and `OVOSAgentPolicy`).
  Tests live in `tests/` (check before adding — do not create a second test
  directory); `tests/e2e/` and `tests/test_e2e_policy.py` self-skip when the
  optional `hivescope` dependency isn't importable.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `pytest tests/ -v`. It uses `FakeBus` from
  `ovos-utils` and mocks for client connections — no running OVOS instance or
  hivemind-core node is required. Coverage: `pytest tests/ --cov=hivemind_ovos_agent_plugin --cov-report=term-missing`.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing outside the
  documented `hivescope`/e2e self-skip.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- `handle_internal_mycroft` is registered as the catch-all `message` handler
  on `OVOSAgentProtocol.register_bus_handlers` — it runs on the bus client's
  handler thread for **every** message on the OVOS bus. Treat it as a hot
  path: no blocking I/O, no per-call logger construction (see the cached
  `_forward_logger()` and its docstring for why), and keep new branches cheap
  for the common case (`context["destination"]` unset or not a peer id).
- Client isolation is enforced in `handle_internal_mycroft`: a message only
  reaches a peer listed in `message.context["destination"]`. Any change here
  must keep one client from ever observing another client's traffic — this is
  the property most worth an adversarial test.
- `self.clients` is mutated from another thread on connect/disconnect; both
  `handle_send` and `handle_internal_mycroft` snapshot it (`list(...)`) before
  iterating, and `handle_send`'s `peer` lookup uses `.get()` rather than
  `in` + index to avoid a `KeyError` race. Preserve that pattern in new code
  that touches `self.clients`.
- `OVOSAgentPolicy.review` is on the auth/admission hot path and fails
  **closed**: a `client.resolve_user(db)` exception becomes
  `Verdict.deny(POLICY_ERROR, ...)`, never a silent allow. Any new mutation or
  DB-backed check added here must preserve that fail-safe direction — never
  fail-open on a lookup or backend error.
- `get_bus()` never blocks: it raises `ConnectionError` immediately if the
  plugin-owned bus isn't connected, because Core calls it inline on the single
  IOLoop thread serving every satellite. Use `wait_for_bus()` instead for
  setup code that can afford to wait; never add a wait inside `get_bus()`.
- Caller-supplied buses (passed via the `bus` field) are never owned or
  connection-managed by this plugin — only a plugin-created bus
  (`self._owned_bus`) is. Keep that distinction when changing bus lifecycle
  code.
- This plugin is the modern replacement for the old OVOS solver-based
  forwarding path; do not add new solver-based code here.
- Never add a new HiveMind bus message type. Extend `HiveMessage`/mutation
  usage within the existing `HiveMessageType` values instead.
